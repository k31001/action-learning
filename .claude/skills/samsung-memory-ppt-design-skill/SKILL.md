# samsung-memory-ppt-design-skill: 삼성 메모리 발표 덱 안티-슬롭 스킬

> 대상: 임원 보고, 기술 심의/리뷰, 과제·액션러닝 보고, 고객/파트너 제안, 학회·컨퍼런스 발표 덱.
> 아래 모든 규칙은 **맥락 조건부**다. 자동으로 전부 적용하지 말고, 먼저 브리프를 읽고 맞는 것만 꺼내 쓴다.
>
> **v2 (2026-09-28)**: 사용자가 확정한 작성 방식을 **11절 시각 우선 작성법**으로 추가했다. 별도 요청이 없으면 11절이 기본값이다. 레퍼런스 구현과 재사용 도구는 `references/visual-first-playbook.md`, `scripts/`에 있다.

---

## 0. DECK READ (장표 만들기 전에 방을 읽어라)

슬라이드를 한 장이라도 만들기 전에, **사용자가 실제로 원하는 덱이 무엇인지 추론**한다. LLM이 만드는 나쁜 덱의 대부분은 기본 템플릿 미학으로 점프해서 생긴다.

### 0.A 먼저 읽을 신호
1. **덱 종류** - 임원 보고 / 기술 심의 / 과제·액션러닝 보고 / 고객 제안 / 학회 발표 / 전시·키노트.
2. **청중** - 사업부장·임원(결론 먼저, 숫자 규율), 기술 심의위원(근거·데이터 밀도), 고객 엔지니어(스펙·벤치마크), 학회 청중(방법론·재현성), 일반 관객(스토리·비주얼). **청중이 미학을 고른다. 내 취향이 아니다.**
3. **보고 시간** - 5분 임원 보고와 30분 기술 리뷰는 장수·밀도·구조가 완전히 다르다. 시간이 안 주어졌으면 덱 종류에서 추론한다.
4. **기존 자산** - 회사/팀 템플릿, 이전 덱, 확정된 목차, 로고·양식. 있으면 그것이 출발점이다(11절 리디자인 프로토콜).
5. **조용한 제약** - 대외비 등급, 미발표 제품 스펙, 고객사 NDA, 사내 보안 규정. 이 제약은 **미적 선호를 무조건 이긴다**(7절).

### 0.B 생성 전에 한 줄 "Deck Read"를 선언한다
장표 작업 전에 반드시 한 줄로 선언: **"이 덱은 \<덱 종류>, 청중은 \<청중>, \<보고 시간/장수> 기준, \<톤> 언어로 읽었습니다."**

예시:
- *"이 덱은 임원 월간 보고, 청중은 사업부 경영진, 10분 8장 기준, 결론 우선 스코어카드 언어로 읽었습니다."*
- *"이 덱은 HBM 고객 기술 제안, 청중은 고객사 SoC 아키텍트, 30분 20장 기준, 스펙·벤치마크 중심 언어로 읽었습니다."*

### 0.C 브리프가 모호하면 질문은 딱 하나만
디자인 방향이 진짜로 갈릴 때만 **하나의** 질문을 한다. 질문 폭탄 금지. 예: *"임원 보고용 요약 덱인가요, 실무 심의용 상세 덱인가요?"* 맥락에서 확신할 수 있으면 묻지 말고 Deck Read를 선언하고 진행한다.

### 0.D 안티-디폴트 규율
다음 디폴트로 도망가지 마라: 파워포인트 기본 테마 색, SmartArt 기본 도형, 3D 파이 차트, 제목+불릿 7줄 벽, 클립아트/이모지 장식, 무지개 색 차트, 슬라이드마다 다른 레이아웃. 이것들이 LLM/사무직 디폴트다. Deck Read에 근거해 의도적으로 그 너머로 간다.

## 1. THE THREE DIALS (핵심 설정)

Deck Read 후 세 개의 다이얼을 설정한다. 아래 모든 레이아웃·밀도·표현 결정은 이 다이얼에 게이트된다.

* **`DATA_DENSITY: 5`** - 1 = 키노트 한 문장, 10 = 심의용 데이터 시트
* **`FORMALITY: 7`** - 1 = 캐주얼 타운홀, 10 = 대외 공식/법무 검토 수준
* **`VISUAL_EXPRESSION: 4`** - 1 = 텍스트·표 위주, 10 = 풀블리드 이미지·키노트급 비주얼

**베이스라인: `4 / 7 / 6`** (v2: 텍스트를 줄이고 시각을 올린 사용자 확정값. v1은 `5 / 7 / 4`). Deck Read가 오버라이드하지 않는 한 이 값을 쓴다. 사용자에게 이 파일을 고치라고 하지 말 것. 오버라이드는 대화로 한다.

### 1.A 덱 종류별 프리셋
| 덱 종류 | DATA_DENSITY | FORMALITY | VISUAL_EXPRESSION | 비고 |
|---|---|---|---|---|
| 임원 보고 (주간/월간/경영현안) | 4 | 8 | 5 | 결론 우선, 스코어카드, 11절 시각 우선 |
| 기술 심의/설계 리뷰 | 8 | 7 | 3 | 근거 데이터 최우선 |
| 과제·액션러닝 보고 | 4 | 7 | 6 | 스토리라인 3장 요약형(11.C), 11절 시각 우선 |
| 고객/파트너 기술 제안 | 7 | 8 | 5 | 스펙·벤치마크 + 브랜드 |
| 학회·컨퍼런스 (ISSCC/FMS류) | 7 | 6 | 5 | 방법론·아키텍처 다이어그램 |
| 전시·키노트/제품 런칭 | 2 | 6 | 9 | 한 장 한 메시지, 풀블리드 |
| 팀 내부 공유/타운홀 | 4 | 4 | 5 | 가볍되 브랜드 토큰 유지 |

### 1.B 다이얼이 출력을 결정하는 방식
* `DATA_DENSITY ≥ 7`: 장당 차트/표 최대 2개 허용, 폰트 최소 12pt 유지, 각주로 조건 명시.
* `DATA_DENSITY ≤ 3`: 장당 메시지 1개 + 시각요소 1개. 표 금지, 숫자는 빅넘버로.
* `FORMALITY ≥ 8`: 유머·이모지·구어체 금지, 단위/출처/기준일 전수 표기.
* `VISUAL_EXPRESSION ≥ 7`: 다크 배경 + 풀블리드 렌더/웨이퍼 이미지 허용. 그 미만이면 화이트 배경 유지.
* `VISUAL_EXPRESSION 5~6` (v2 기본): 화이트 배경을 유지하되 **장마다 그래프·도형·로고·부품 이미지가 텍스트보다 넓은 면적**을 차지한다. 불릿 목록 대신 11절의 도형 어휘를 쓴다.

교차 참조는 반드시 이 변수명 그대로 쓴다. `DENSITY_LEVEL` 같은 별칭을 만들지 마라.

## 2. SAMSUNG MEMORY 디자인 토큰

### 2.A 컬러 시스템
**원칙: 화이트 배경 + 뉴트럴 그레이 + Samsung Blue 단일 액센트.** 삼성 브랜드의 본질은 절제다.

| 토큰 | 값 | 용도 |
|---|---|---|
| `--samsung-blue` | `#1428A0` | 유일한 주 액센트. 강조 숫자, 핵심 바, 헤더 라인 |
| `--blue-tint-1` | `#3C5AC8` (또는 blue 60% tint) | 보조 계열 데이터, 호버·서브 강조 |
| `--blue-tint-2` | `#AAB8E8` 계열 | 배경 밴드, 비강조 계열 데이터 |
| `--ink` | `#1A1A1A` | 본문 텍스트. **순수 검정 `#000000` 금지** |
| `--gray-strong` | `#555555` | 보조 텍스트, 축 레이블 |
| `--gray-line` | `#D9D9D9` | 표 괘선, 구분선. 굵기 0.5~0.75pt |
| `--bg` | `#FFFFFF` | 기본 배경 |
| `--positive` | `#00A651` 계열 녹색 | 개선/달성 **의미 전달에만** |
| `--negative` | `#D93025` 계열 적색 | 리스크/미달 **의미 전달에만** |

**하드 룰:**
* 한 덱에 액센트는 Samsung Blue **하나**. 슬라이드마다 색이 바뀌면 실패.
* 녹색/적색은 실제 의미(달성/리스크)가 있을 때만. 장식용 금지.
* 그라데이션은 `VISUAL_EXPRESSION ≥ 7`인 키노트 배경에서만, 그 외 도형·차트에 금지.
* 경쟁사 데이터는 **뉴트럴 그레이**, 자사 데이터는 Samsung Blue. 경쟁사에 빨강 칠하지 마라(유치하고 대외 리스크).

### 2.B 타이포그래피
* **1순위:** SamsungOne (사내 배포 폰트). 국문 SamsungOneKorean.
* **폴백(사외 PC/미설치 환경):** 국문 Pretendard 또는 Noto Sans KR, 영문 Arial. **맑은 고딕을 디자인 선택으로 쓰지 마라. 폴백 최후순위다.**
* 한 덱에 폰트 패밀리는 **1개**(굵기 변형만 허용). 제목용 폰트 따로 본문용 따로 금지.
* 크기 체계(16:9, 33.87×19.05cm 기준): 슬라이드 타이틀 20~24pt Bold / 리드 메시지 14~16pt / 본문 12~14pt / 각주·출처 9~10pt. **10pt 미만은 각주 외 금지.**
* **v2 작은 글자 금지**: 본문 최소는 표준 캔버스 12pt(20×11.25in 캔버스 18pt), 차트 눈금·범례 최소 11pt(16pt), 출처 줄만 10pt(15pt). 캔버스별 환산은 11.B 표. 글이 칸에 안 들어가면 글자를 줄이지 말고 **문장을 줄인다**.
* 강조는 **굵기와 Samsung Blue로**, 크기 폭주나 밑줄·기울임 남발로 하지 않는다.
* 자간·행간: 국문 행간 1.15~1.3. 국문 장평 조작 금지.

### 2.C 그리드·마진
* 16:9 고정. 상하좌우 안전 마진 최소 1.2cm. 로고·페이지번호 등 고정 요소는 마스터에만 둔다.
* 12컬럼 멘탈 그리드. 본문 영역을 1단(풀), 2단(7:5 또는 8:4), 3단 중 하나로만 분할. 4단 이상 금지.
* 정렬은 **좌측 정렬이 기본**. 가운데 정렬은 타이틀 슬라이드와 섹션 브릿지에만.
* 개체 간 간격은 4의 배수(px 기준) 감각으로 균질하게. "대충 맞음"은 없다. 스냅·정렬 기능으로 픽셀 단위 정렬.

### 2.D 로고·양식 규율
* 로고는 마스터 지정 위치(통상 우상단 또는 우하단) 한 곳에만, 크기 변경 금지, 본문 개체와 겹침 금지.
* 문서 등급 표기(대외비 등급)는 지정 위치에 전 장 동일하게(7절).
* 페이지 번호는 표지 제외 전 장. 목차와 실제 장 구성이 일치해야 한다.

## 3. 슬라이드 아키텍처

### 3.A 액션 타이틀 (헤드라인 = 결론)
* 모든 본문 슬라이드의 타이틀은 **주어+서술어가 있는 결론 문장**이다. "HBM4 개발 현황"(토픽 라벨) 금지 → "HBM4 샘플 수율, 목표 대비 +3%p로 일정 리스크 해소"(액션 타이틀).
* 타이틀만 읽어도 덱 전체 스토리가 이어져야 한다(타이틀 스캔 테스트, 9절 체크).
* 타이틀은 2줄 이내. 2줄을 넘으면 메시지가 정리 안 된 것이다. 슬라이드를 쪼개라.

### 3.B 1 슬라이드 1 메시지
* 장당 핵심 메시지 1개. 메시지가 2개면 슬라이드도 2장이다.
* 구조: **타이틀(결론) → 리드 메시지 1~2줄(근거 요약) → 바디(차트/표/다이어그램 1~2개) → 각주(출처·조건)**.
* 임원 보고(`DATA_DENSITY ≤ 5`)는 바디 시각요소 1개가 기본.

### 3.C 레이아웃 패밀리 (한 덱에서 최소 3종 이상 순환)
1. **스코어카드** - KPI 그리드(빅넘버 + 전기 대비 델타 + 상태). 임원·과제 보고의 앵커.
2. **빅넘버 + 근거** - 좌측 거대 숫자 1개, 우측 근거 차트/불릿.
3. **비교 컬럼** - 2~3안 대안 비교, 동일 속성 행 정렬(As-Is/To-Be 포함).
4. **타임라인/로드맵** - 좌→우 시간축, 마일스톤 다이아몬드.
5. **아키텍처 블록도** - 계층·데이터 경로 다이어그램(5.C).
6. **풀블리드 브릿지** - 섹션 전환용, 텍스트 최소(키노트·제안 덱).
동일 패밀리 3장 연속 금지. 단, 심의 덱의 데이터 연속 장은 예외.

### 3.D 덱 스토리라인 (과제·액션러닝/임원 보고 기본형)
`배경·문제 정의 → 목표(정량) → 접근/실행 → 결과(스코어카드) → 남은 리스크와 대응 → 다음 단계 요청사항`.
첫 장 요약(Executive Summary) 1장에 이 전체가 압축되어야 하고, 임원이 그 한 장만 봐도 의사결정 가능해야 한다.

## 4. 디자인 지침 (바이어스 교정)

### 4.1 차트
* **차트 종류는 질문이 고른다:** 추세=라인, 비교=가로/세로 바, 구성=100% 누적 바(파이는 항목 3개 이하일 때만), 분포=히스토그램, 상관=산점도. **3D 차트, 도넛 남발, 방사형(레이더) 기본 사용 금지.**
* 데이터 계열 색: 자사/주인공 = Samsung Blue, 나머지 = 그레이 톤 2~3단. 계열이 5개를 넘으면 차트를 쪼개거나 질문을 다시 정의하라.
* 범례보다 **직접 레이블링**(계열 끝에 이름 붙이기)을 우선. 범례가 필요하면 차트 위·아래 한 줄.
* 격자선은 가로만, `--gray-line` 0.5pt. 축은 0 기준 시작이 원칙(로그 스케일·구간 확대 시 반드시 명기).
* 강조 포인트는 1개 차트에 1곳만: 해당 바/포인트만 Blue, 콜아웃 한 줄.
* 모든 차트에 단위·기간·조건(온도, 전압, 워크로드 등)을 축 또는 각주에 명기.

### 4.2 표
* 표는 "조회용 데이터"일 때만. 비교 메시지면 차트로 바꿔라.
* 괘선 최소주의: 헤더 아래 1줄 + 행 사이 옅은 가로선만. 세로선·전체 테두리 금지. 셀 배경 얼룩덜룩 금지(헤더 행 1색만 허용).
* 숫자 우측 정렬, 소수 자릿수 통일, 천 단위 구분. 강조 셀은 굵기+Blue, 형광펜식 배경 금지.
* 10행을 넘는 표는 백업(Appendix)으로 보내고 본문에는 요약 행만.

### 4.3 다이어그램
* SmartArt 기본형 금지. 사각형+직선/직각 커넥터로 직접 그린다.
* 도형 스타일 통일: 라운드 코너 1가지 반경(예: 4pt), 채움은 화이트/그레이 톤 + 강조 블록만 Blue, 외곽선 0.75pt. 그림자·입체 효과 금지.
* 화살표는 데이터/신호 흐름 등 **실제 방향성이 있을 때만**. 장식 화살표 금지.
* 텍스트가 도형 밖으로 넘치면 도형을 키우지 말고 텍스트를 줄여라.

### 4.4 아이콘·이미지
* 아이콘은 단색 라인 스타일 1개 패밀리로 통일(예: 사내 아이콘 세트, 없으면 Phosphor/Tabler 계열). 클립아트·3D 아이콘·이모지 금지.
* 제품 이미지는 공식 렌더/실사만. 웨이퍼·다이샷·보드 사진은 해상도와 보안 등급 확인 후 사용(7절).
* **v2 부품은 사진으로, 기업은 로고로** (11.F, 11.G): NAND·DRAM·HBM·SSD·서버·GPU를 말할 때는 글자 대신 실물 이미지를 놓는다. 공식 사진을 구할 수 없는 환경이면 3D 렌더로 대신하고 교체 폴더를 남긴다. 기업명은 로고로 쓰고, 로고가 없으면 워드마크 칩(테두리 상자 + 볼드 텍스트)으로 쓴다.
* 스톡 사진으로 "협업하는 사람들" 같은 분위기 컷 넣지 마라. 반도체 덱에서 그것은 소음이다.

### 4.5 애니메이션·전환
* 기본값: **전환 없음, 애니메이션 없음.** 보고 덱은 인쇄·PDF 공유가 전제다.
* 허용 예외: 키노트/전시 덱(`VISUAL_EXPRESSION ≥ 7`)에서 페이드 계열만. 회전·바운스·타자기 효과는 어떤 경우에도 금지.
* 복잡한 다이어그램의 단계 설명이 필요하면 애니메이션 대신 **장을 쪼개서** 점진 공개한다(인쇄 호환).

## 5. 반도체 도메인 콘텐츠 패턴

### 5.A 로드맵 슬라이드
* 가로 시간축(분기/연도), 제품 세대는 행(swimlane)으로. 세대 전환점에 다이아몬드 마일스톤.
* 확정 일정은 실선/진한 블록, 계획·검토 중은 점선/틴트 블록으로 **시각적으로 구분**하고 범례에 명기.
* 미발표 세대 명칭·일정은 7절 보안 규율 선적용.

### 5.B 벤치마크·경쟁 비교
* 가로 바 차트 기본. 자사 = Samsung Blue, 경쟁/이전 세대 = 그레이. 기준선(이전 세대=1.0) 정규화 시 기준 명시.
* 측정 조건(플랫폼, FW 버전, 워크로드, QD, 온도)을 각주에 전수 기재. 조건 없는 벤치마크 숫자는 싣지 않는다.
* "최대 N배" 류 마케팅 수치와 실측 평균을 섞지 마라. 섞이면 심의에서 신뢰를 잃는다.

### 5.C 아키텍처 블록도
* 계층 규율: 호스트(CPU/PCIe) → 컨트롤러(FE/FTL/BE) → 미디어(DRAM/NAND) 순의 일관된 상하 또는 좌우 방향.
* 데이터 경로는 굵은 실선, 제어/메타 경로는 가는 점선. 대역폭·레이턴시 등 정량 정보는 경로 위 작은 레이블로.
* 변경·신규 블록만 Blue로 하이라이트하고 나머지는 그레이로 눌러라. "이번에 뭐가 달라졌는가"가 한눈에 보여야 한다.

### 5.D 수율·품질·신뢰성 트렌드
* 라인 차트 + 목표선(가로 점선, 레이블 필수). 목표 대비 갭은 델타 콜아웃으로.
* 관리 한계선/스펙 한계선을 함께 표기할 때 선 스타일을 구분하고 범례 필수.
* Y축 구간 확대로 개선을 과장하지 마라. 확대했다면 축 절단 표기(물결)와 각주로 정직하게.

### 5.E 전력·TCO 스토리
* 고객 제안 덱의 클로징 패턴: 성능/W 또는 TCO 절감액 빅넘버 1개 + 산출 근거 표(백업 연결).
* 가정(전력 단가, 서버 수, 수명)을 각주에 명시. 가정 없는 TCO 숫자는 금지.

## 6. PPT 슬롭 TELLS (금지 패턴)

브리프가 명시적으로 요구하지 않는 한 아래 시그니처를 금지한다.

### 6.A 시각
* **SmartArt 기본형** (기본 색 프로세스/순환/피라미드) 금지.
* **3D 효과 전부** 금지: 3D 차트, 입체 도형, 반사, 경사(bevel), 워드아트.
* **무지개 팔레트** 금지. 계열 색은 Blue + 그레이 체계(2.A)만.
* **형광펜 강조** (노란 배경 텍스트) 금지. 굵기+Blue로.
* **슬라이드마다 다른 배경/테마** 금지. 덱 전체 1테마 락.
* **그림자 남발** 금지. 도형·텍스트 그림자는 기본 0.

### 6.B 텍스트
* **불릿 벽** 금지: 장당 불릿 최대 5개, 불릿당 1줄(최대 1.5줄). 그 이상이면 구조화(표/다이어그램)하거나 장을 쪼갠다.
* **토픽 라벨 타이틀** 금지(3.A 액션 타이틀 강제).
* **긴 문장 통째로 붙여넣기** 금지. 슬라이드는 문서가 아니다. 서술은 스크립트/별첨 문서로.
* **"~화", "~적 시너지", "혁신적", "차세대" 남발** 금지. 정량 표현으로 대체: "성능 개선" → "랜덤 리드 +18%".
* **이모지 금지**(FORMALITY ≥ 6 전 구간). 타운홀 덱에서만 절제 허용.
* **em-dash(—) 전면 금지.** 제목, 본문, 각주, 콜아웃 어디에도. 마침표, 쉼표, 콜론, 괄호로 재구성. en-dash(–)도 구분자로 금지, 범위는 하이픈(-) 사용. 이 규칙은 비협상이다.

### 6.C 데이터
* **가짜-완벽 숫자** 금지: `99.99%`, `2배`, `1234` 같은 티 나는 수치 대신 실제 근거 수치. 근거가 없으면 `[실측치 입력]` 플레이스홀더를 명시적으로 남겨라. **수치를 지어내는 것이 최악의 실패다.**
* **출처 없는 시장 数字** 금지. 시장 전망은 기관명+발행 시점 필수(예: 조사기관, 발행 분기).
* **단위 없는 축** 금지.

### 6.D 구조
* **목차 15개 항목** 같은 과잉 목차 금지. 섹션 3~5개.
* **"감사합니다" 클로징 장에 이미지만** 넣지 마라. 클로징은 요청사항/의사결정 포인트 요약 장이다(Q&A 장은 선택).
* **백업 없는 본문 과밀** 금지. 상세 데이터는 Appendix로 보내고 본문 장에서 "상세: 백업 p.N" 연결.

## 7. 보안·기밀 규율 (모든 미학에 우선)

* 덱 생성 시작 시 **문서 등급을 먼저 확인**하고 전 장 지정 위치에 동일 표기. 사용자가 등급을 안 줬으면 물어보지 말고 `[문서등급 표기]` 플레이스홀더를 넣고 안내한다.
* 미발표 제품의 코드명/스펙/일정, 수율·원가 실측치, 고객사명이 포함되면: 실제 값 대신 플레이스홀더를 쓰고, 해당 장에 각주로 "보안 검토 필요" 마킹을 남긴다. **이 스킬은 실제 기밀 수치를 생성하거나 추정해서 채우지 않는다.**
* 대외 덱(고객/학회)에서는 내부 조직명, 내부 시스템명, 미공개 로드맵 항목이 남아있는지 프리플라이트에서 별도 확인(9절).
* 웨이퍼·다이샷·레이아웃 이미지는 보안 등급 확인 전 사용 금지 플레이스홀더 처리.

## 8. 리디자인 프로토콜 (기존 덱 개선 요청 시)

* **첫 행동은 감사(audit)다.** 기존 덱의 스토리라인, 액션 타이틀 여부, 색·폰트 일관성, 장당 메시지 수, 데이터 출처 표기를 먼저 진단하고 3~5줄로 보고한다.
* **보존 우선 모드가 기본:** 확정된 데이터, 승인된 문구, 조직 템플릿 요소는 유지하고 시각 규율(2·4·6절)만 정렬한다.
* **전면 재구성**은 사용자가 명시적으로 요청할 때만: 스토리라인(3.D)부터 다시 세우고 장을 재배치한다.
* 침묵 속에 바꾸면 안 되는 것: 수치, 결론 문장의 의미, 문서 등급, 목차 순서(재구성 승인 전).

## 9. FINAL PRE-FLIGHT CHECK

출력 전에 전 항목을 점검한다. **선택이 아니다. 하나라도 실패하면 덱은 완성이 아니다.**

- [ ] **Deck Read** 한 줄 선언했는가(0.B)?
- [ ] **다이얼 값**을 브리프에서 추론해 명시했는가(베이스라인 무단 사용 아님)?
- [ ] **문서 등급** 표기 또는 플레이스홀더가 전 장에 있는가(7절)?
- [ ] **기밀 값 미생성**: 미발표 스펙·수율·원가·고객명을 지어내지 않고 플레이스홀더 처리했는가?
- [ ] **타이틀 스캔 테스트**: 슬라이드 타이틀만 위에서 아래로 읽어서 스토리가 완결되는가?
- [ ] **액션 타이틀**: 토픽 라벨 타이틀이 0장인가?
- [ ] **1장 1메시지**: 메시지 2개짜리 장이 없는가?
- [ ] **Executive Summary 1장**으로 의사결정이 가능한가(임원/과제 덱)?
- [ ] **컬러 락**: 액센트는 Samsung Blue 하나, 녹/적은 의미 전달에만 쓰였는가?
- [ ] **순수 검정(#000000) 텍스트 0**인가?
- [ ] **폰트 패밀리 1개**, 크기 체계(2.B) 준수, 각주 외 10pt 미만 0인가?
- [ ] **em-dash(—) 0개**인가? (6.B, 비협상)
- [ ] **SmartArt 기본형·3D·워드아트·클립아트·이모지 0**인가?
- [ ] **불릿 규율**: 장당 ≤5개, 불릿당 ≤1.5줄인가?
- [ ] **모든 차트**에 단위·기간·측정 조건·출처가 있는가?
- [ ] **자사=Blue, 경쟁=그레이** 계열 색 규율을 지켰는가?
- [ ] **축 정직성**: 0 기준 시작 또는 절단 명기, 과장 스케일 없는가?
- [ ] **표 괘선 최소주의**(세로선·전체 테두리 없음)를 지켰는가?
- [ ] **레이아웃 패밀리** 3종 이상 순환, 동일 패밀리 3장 연속 없는가?
- [ ] **정렬 픽셀 단위**: 개체 간 간격 균질, 마진 침범 0인가?
- [ ] **애니메이션·전환 0**(키노트 예외 제외), 인쇄/PDF에서 정보 손실 없는가?
- [ ] **10행 초과 표·상세 데이터**는 Appendix로 갔는가?
- [ ] **클로징 장**이 요청사항/의사결정 포인트를 담는가?
- [ ] **대외 덱**이라면 내부 조직명·미공개 항목이 제거되었는가?
- [ ] **(v2) 시각 우선**: 장마다 사실은 그래프, 개념은 도형·선으로 표현했고 불릿 목록이 0인가(11.A)?
- [ ] **(v2) 작은 글자 0**: 본문 18pt(20in 캔버스) 이상, 출처 줄만 15pt인가? 자동 감사 스크립트로 확인했는가(11.I)?
- [ ] **(v2) 제목 줄바꿈**: 2줄 제목은 의미 단위로 수동 줄바꿈해 한 단어가 홀로 남지 않는가?
- [ ] **(v2) 로고·이미지**: 기업은 로고, 부품은 이미지로 나왔는가? 3D 렌더를 썼다면 출처 줄에 "3D 렌더"라고 적고 교체 폴더를 안내했는가?
- [ ] **(v2) 해석 표지**: 과거 의사결정의 원인처럼 해석이 들어간 도형에 "복기" 같은 라벨을 달아 사실과 구분했는가? 사내 수치는 `[사내 확인]`인가?
- [ ] **(v2) 렌더 QA**: PDF로 변환해 넘침·겹침·잘림을 눈으로 확인하고 고쳤는가?

하나라도 정직하게 체크할 수 없으면 고치고 나서 전달한다.

## 11. 시각 우선 작성법 (Visual-first, v2 기본값)

> 출처: 2026-09-28 "다운턴에서 배운 SSD 생존 전략" 3장 덱. 사용자가 "의도한 대로 나왔다"고 확정한 방식이다. 레퍼런스 구현은 `references/visual-first-playbook.md`(좌표·코드), 재사용 도구는 `scripts/`.

### 11.A 다섯 가지 원칙

| 원칙 | 규칙 | 하지 않는 것 |
|---|---|---|
| **텍스트를 줄인다** | 장당 글은 제목 2줄 + 구획 제목 + 한 줄 캡션 + 밴드 한 줄. 서술은 발표자 노트로 보낸다 | 불릿 목록, 문단, 리드 메시지 두 줄 |
| **사실은 그래프로** | 수치가 있으면 반드시 차트(선·막대·로그 축·빅넘버). 직접 레이블, 강조는 Blue 한 곳 | 숫자 나열 표, 수치를 문장에 묻기 |
| **개념은 도형과 선으로** | 체인(상자 → 화살표 → 상자), 괄호(범위), 계층 격자(층 × 단계), 계단(진화), 적층(더해지는 것), 순환 화살표(함께 만든다), 사람 아이콘(조직·상주) | SmartArt, 장식 화살표, 클립아트 |
| **기업은 로고로** | 범례·벤치마크·고객 줄은 로고. 로고가 없으면 워드마크 칩 | 기업명을 본문 글자로만 쓰기 |
| **부품은 실물 이미지로** | NAND·DRAM·HBM(GPU 패키지)·SSD·서버는 이미지. 흐름(HBM → DRAM → SSD, NAND → SSD → 서버)을 이미지 체인으로 | 부품을 사각형 라벨로만 그리기, 분위기 스톡 사진 |

### 11.B 캔버스와 글자 크기

보고 덱 캔버스는 **20 × 11.25in**(16:9, python-pptx `Emu(18288000) × Emu(10287000)`)를 쓴다. 표준 13.33 × 7.5in 대비 1.5배라 pt도 1.5배로 잡는다.

| 요소 | 20in 캔버스 | 표준 캔버스 환산 |
|---|---|---|
| 슬라이드 제목 (2줄, 수동 줄바꿈) | 32pt Bold | 21pt |
| 구획 제목 ("라벨: 한 줄 결론") | 24pt Bold | 16pt |
| 본문·도형 안 글자·캡션 | 18~22pt | 12~15pt |
| 빅넘버 | 44~48pt Bold | 30pt |
| 차트 눈금·범례 | 16~18pt | 11~12pt |
| 출처 줄 (최대 2줄) | 15pt | 10pt |

- 제목은 **의미 단위에서 수동으로 줄바꿈**한다(`"앞 절,\n뒤 절"`). 자동 줄바꿈으로 한 단어가 둘째 줄에 홀로 남으면 실패다.
- 덱 전체 제목을 이어 읽으면 한 문단이 되도록 쓴다(3.A 타이틀 스캔 테스트의 강화형).
- 구획 제목은 `라벨: 결론` 형태로 13~15자 이내(교훈: … / 다음 수요: … / 새 요구: …).

### 11.C 레이아웃 템플릿 4종 (20 × 11.25in 좌표)

공통 골격: 상단 줄(0.40in: 덱 이름 Blue 18pt · `n / N  섹션` 그레이 · 우측 문서등급) → 제목(0.86in, 32pt 2줄) → 구분선(2.12in) → 본문(2.34 ~ 9.45in) → **Blue 밴드**(9.60in, 높이 0.80: 명제·결론·시작 과제) → 출처 줄(10.50in, 15pt 2줄) + 쪽 번호.

1. **3패널 스토리 + 명제 밴드** (배경·문제 제기): 폭 5.6 / 6.6 / 5.4in 세 구획을 쉐브론으로 잇는다. 구획마다 번호 원 + `라벨: 결론` + 시각 1~2개(차트, 이미지 체인, 빅넘버). 예: ① 교훈(점유율 선 그래프 + 복기 3단 + 인용 상자) → ② 다음 수요(부품 이미지 체인 + 누적 막대) → ③ 새 요구(로그 축 막대 + 빅넘버) → 명제 밴드.
2. **상단 1/3 범위 체인 + 하단 2/3 단계 격자** (솔루션): 위는 부품 이미지 체인(NAND → SSD → 서버)과 "문제 → 해법" 줄, 범위 괄호 두 개("지금까지" 그레이 / "이제" Blue), 우측에 선택지 상자(하나만 Blue). 아래는 **계층 × 단계 격자**(행 = 기술 스택 층, 열 = 단계). 해법이 사는 칸만 채우고, 마지막 단계만 Blue로 위층까지 채워 "해법이 위로 올라간다"를 보인다. 격자 아래에 핵심 지표 한 줄(예: WAF ≈3 → 1). 결론 밴드 오른쪽에 다음 장으로 이어지는 알약(기술 · 인재 · 고객 협력).
3. **지금 → 앞으로 3열 + 벤치마크 줄** (실행): 폭 5.55 / 6.90 / 5.55in. 열마다 번호 원 + `라벨: 결론`, 그 아래 벤치마크 줄(로고 + 한 줄), "지금"(그레이 도형) → 아래 삼각형 → "앞으로"(Blue 도형), 맨 아래 Blue 캡션 한 줄. 가운데 열을 가장 넓게 써 핵심 메시지(예: 고객 상주 순환)를 둔다.
4. **로드맵 매트릭스** (단계 × 축): 열 = 단계(오각형 화살표 헤더, 시계 표시), 행 = 축. 한 행은 계단(높이가 오르는 블록)으로 진화를 그린다. 3장 연속으로 쓰지 않는다.

### 11.D 차트 규칙 (matplotlib)

- **그림 크기 = 슬라이드 배치 크기(인치)**로 만들어 차트 pt = 슬라이드 pt가 되게 한다. `dpi=300`, `transparent=True`.
- 한글 폰트는 `font_manager.addfont()`로 NanumGothic(Regular·Bold)을 등록한다.
- 범례 대신 **직접 레이블**. 기업 계열의 범례는 차트 밖 **로고 + 색 막대**로 슬라이드에 그린다.
- 전망 구간은 세로 점선 + "전망 →". 여러 자릿수에 걸친 비교(DWPD 0.3 ~ 30)는 **로그 축**을 쓰고 축에 "(로그 축)"을 적는다.
- 보조 지표 줄(예: QLC 비중 %)은 x축 아래 한 줄로 넣고 강조 값 하나만 Blue.
- 기관이 섞인 시계열은 출처 줄에 기관과 기준 차이를 적고 추세로 읽게 한다.

### 11.E 개념 도형 어휘

| 말하려는 것 | 도형 |
|---|---|
| 원인 → 결과 | 둥근 상자 3개 + 그레이 화살표, 마지막 상자만 Blue |
| 범위가 넓어진다 | 위쪽 괄호 두 개(그레이 "지금까지" / Blue "이제") |
| 해법이 위로 올라간다 | 계층 × 단계 격자, 마지막 단계만 Blue로 위층까지 |
| 세 갈래 중 하나를 고른다 | 둥근 줄 3개, 고른 줄만 Blue 채움 + 오른쪽에 대가(비용 ↑ · 용량 ↓ · TCO 유지) |
| 무엇이 더해진다 | 적층 막대(아래 = 기존, 위 = 추가), 선택 항목은 점선 테두리, 오른쪽 괄호로 묶어 이름 붙이기 |
| 진화한다 | 계단 블록(높이 증가), 먼 미래는 점선 |
| 멀리서 문서로 협력 | 두 상자 사이 가는 선 + 문서 도형(FOLDED_CORNER) |
| 고객 안에 들어가 함께 만든다 | 고객 경계(틴트 + Blue 테두리) 안에 사람 아이콘(자사 Blue, 고객 그레이) + 양방향 화살표 "매일 함께", 본사 줄과의 **아래 화살표(사람) / 위 화살표(실제 요구 → 제품)** 순환 |
| 역량의 빈칸 | 층 × (지금 / 필요) 격자: 지금 = 강점 그레이 · 일부 연회색 · 없음 점선, 필요 = Blue |
| 결정적 격차 | 빅넘버("최대 100배") + 한 줄 근거 |

사람 아이콘은 머리 원 + 위가 둥근 몸통(`ROUND_2_SAME_RECTANGLE`) 두 도형으로 그린다(`scripts/deck_helpers.py` `person()`).

### 11.F 로고

- 우선순위: 사내 공식 로고 → 레포 `assets/logos/` → npm `@iconify-json/logos`(컬러) · `@iconify-json/simple-icons`(단색, 잉크 #1A1A1A로 칠함)를 headless Chromium으로 PNG 렌더(`scripts/render_parts/render.mjs logos`) → 워드마크 칩.
- 로고는 **식별 표시**다. 크기를 맞추려 늘이지 말고 높이만 지정한다(워드마크 0.25~0.30in, 심볼형 0.34~0.46in).
- 자사 = Blue, 경쟁 = 그레이 규칙은 **데이터 계열 색**에 적용하고, 로고는 원래 색을 쓴다.
- 쓰는 자리: 차트 범례(삼성 · SK하이닉스), 벤치마크 줄(Micron ↔ Anthropic, Palantir), 대상 고객 줄(NVIDIA · Meta · Google · Microsoft · AWS), 인용 상자의 고객.

### 11.G 부품 이미지

- 우선순위: 사내 공식 제품 사진(배경 제거 PNG) → 공개 공식 이미지 → **3D 렌더**(`scripts/render_parts/`, three.js + headless Chromium: `nand`, `dram`, `hbm`, `ssd`, `server`).
- 생성기는 `assets/photos/<이름>.(png|jpg)`가 있으면 그것을, 없으면 `render_<이름>.png`를 쓴다. 사진을 넣고 다시 돌리면 교체된다.
- 이미지는 투명 배경으로 **여백을 잘라** 박스 안에 비율 유지로 맞춘다(`fit()`). 부품 이름은 이미지 아래 18~20pt.
- 3D 렌더를 썼으면 출처 줄에 "부품 이미지는 3D 렌더"라고 적는다. 사진인 척하지 않는다.
- 외부 이미지 호스트가 막힌 환경(프록시 403)에서는 먼저 막힘을 확인하고 렌더로 간다. 사용자에게 교체 폴더를 알려 준다.

### 11.H 사실 규율 추가

- **해석과 사실을 도형으로 구분**: 과거 의사결정의 원인처럼 해석이 들어간 도형 묶음에는 "복기" 같은 라벨을 달고, 사실은 그래프가 맡는다.
- 공개 근거가 없는 사내 요구 수치는 `[사내 확인]`을 출처 줄에 적는다.
- 인과를 과장하지 않는 동사: "이동"보다 "내려온다 / 더해진다"처럼 근거가 받치는 말을 고른다.
- 벤치마크는 공개된 구성요소만 쓰고(예: 계약 4요소), 재무 조건이 비공개면 비공개라고 적는다. 우리 범위 밖 요소는 점선 "(선택)"으로 둔다.

### 11.I 렌더 QA 루프 (완성 전 필수)

1. 생성기를 `FONT_LATIN=NanumGothic FONT_EA=NanumGothic OUT_PATH=<scratch>.pptx`로 돌린다.
2. `soffice --headless --convert-to pdf` → PyMuPDF로 PNG 렌더 → 장마다 눈으로 확인: 제목 줄바꿈, 로고·글자 겹침, 칸 넘침, 차트 레이블 잘림, 출처 줄 3줄 넘침.
3. `scripts/qa_audit.py <pptx>`로 **최소 pt, em-dash, 노트 em-dash**를 자동 감사한다.
4. 고친 뒤 다시 1로. 최종본은 기본 폰트로 한 번 더 생성한다.

`scripts/qa_render.sh <generator.py> <scratch_dir>`가 1~3을 한 번에 한다.
