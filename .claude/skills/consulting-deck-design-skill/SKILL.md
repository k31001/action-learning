# consulting-deck-design-skill: 전략 컨설팅 보고 덱 문법

> 대상: 경영진 전략 보고, 사업 진단→권고, 전략 옵션 평가, 투자 심의, 실행 로드맵 덱.
> 원칙: **한 장이 아니라 한 줄이 먼저다.** 덱은 제목만 이어 읽어도 논증이 완결되어야 한다(ghost deck). 장식은 논리를 이길 수 없다.
> 다른 디자인 스킬과의 관계: 컬러·폰트·브랜드 규율은 조직 스킬이 결정한다. 이 스킬은 **무엇을, 어떤 순서로, 어떤 구조로 말할지**를 결정한다. 충돌 시 브랜드 토큰은 조직 스킬, 논리·레이아웃은 이 스킬을 따른다.

---

## 0. DECK READ: 만들기 전에 답을 먼저 쓴다

컨설팅 덱은 슬라이드를 그리기 전에 **답(Governing Thought) 한 문장**을 쓴다. 답이 없으면 덱을 만들 수 없다.

1. **질문(Key Question)**: 청중이 의사결정해야 할 단 하나의 질문. 예: "다운턴에도 완제품 SSD 부가가치를 지키려면 개발실은 무엇을 해야 하는가"
2. **답(Governing Thought)**: 질문에 대한 한 문장 답. 결론이자 이그제큐티브 서머리의 첫 줄.
3. **논거 3개(Key Lines)**: 답을 지지하는 MECE한 논거. 2개면 빈약하고 5개면 기억 못 한다.
4. **청중과 결정**: 누가 듣고, 이 덱으로 무엇을 결정하는가. 결정이 없으면 덱이 아니라 자료집이다.

선언 형식 (작업 전 한 줄):
**"Key Question은 \<질문>, 답은 \<한 문장>, 논거는 \<3개>, 청중은 \<누구>가 \<무엇>을 결정합니다."**

---

## 1. 스토리 구조: Pyramid Principle

### 1.A 피라미드
- **꼭대기**: 답 한 문장 (Governing Thought)
- **2층**: 답을 지지하는 논거 3개 (Key Lines). 서로 겹치지 않고(ME) 합치면 답을 완성(CE)
- **3층**: 각 논거를 지지하는 근거(데이터·사례·인용). 근거는 반드시 출처가 있다
- 덱의 순서 = 피라미드를 위에서 아래로 읽는 순서. **결론이 맨 앞**, 근거는 뒤.

### 1.B 도입은 SCQA
이그제큐티브 서머리 또는 첫 장은 SCQA로 연다.
- **S(Situation)**: 청중이 이미 동의하는 현재 상황
- **C(Complication)**: 상황을 문제로 만드는 변화
- **Q(Question)**: 그래서 생기는 질문
- **A(Answer)**: 답 = Governing Thought

### 1.C 두 가지 논리 검사
- **수평 논리(Horizontal)**: 슬라이드 액션 타이틀만 순서대로 읽으면 논증이 완결되는가. 완결되지 않으면 장이 빠졌거나 순서가 틀린 것.
- **수직 논리(Vertical)**: 각 장의 본문이 그 장의 타이틀을 실제로 증명하는가. 본문에 있는데 타이틀에 없는 메시지는 삭제하거나 타이틀을 고친다.

### 1.D MECE
- 옵션·요인·세그먼트를 나열할 때 **겹침 없이, 빠짐 없이**. "기타"는 MECE 실패의 자백이다.
- 3~4개 묶음이 기본. 7개 이상이면 상위 개념으로 다시 묶는다.

## 2. 슬라이드 문법

### 2.A 액션 타이틀 (Action Title)
- **완전한 문장**으로 그 장의 so-what을 쓴다. 주제어("시장 현황")가 아니라 주장("시장은 2년 내 절반으로 줄고, 회복은 니즈를 적중한 벤더가 가져갔다").
- 최대 2줄. 숫자가 있으면 넣는다. 타이틀 크기는 **18~22pt** (키노트식 32pt 아님: 문장을 담아야 한다).
- 타이틀만 복사해 목차로 붙이면 요약문이 되어야 한다.

### 2.B 한 장 한 메시지
- 장당 메시지 하나. 두 개면 두 장으로 나눈다.
- 본문의 모든 요소(차트·표·박스)는 타이틀을 증명하는 근거다. 증명에 기여하지 않는 요소는 삭제.

### 2.C 필수 장치
| 장치 | 위치 | 역할 |
|---|---|---|
| **트래커(Tracker)** | 상단 좌측, 소형 회색 | 덱 전체 구조에서 현재 위치 ("배경 › 2023 다운턴") |
| **액션 타이틀** | 상단, 헤어라인 위 | 이 장의 주장 |
| **리드인(Lead-in)** | 타이틀 아래 1줄 (선택) | 본문 읽는 법 또는 범위·단위·기준 |
| **스티커(Sticker) / So-what 박스** | 하단 또는 우측 | 본문에서 끌어낸 함의 한 문장. 타이틀의 반복이 아니라 "그래서 우리는" |
| **출처·각주 줄** | 최하단 좌측, 8~9pt | 데이터 출처·기준일·계산 방법·제외 사항 |
| **슬라이드 번호** | 최하단 우측 | 토론 중 참조용 |

### 2.D 이그제큐티브 서머리 장
- 첫 장. 덱 전체를 한 장으로 압축. 청중이 이 장만 읽고 나가도 결정할 수 있어야 한다.
- 구조: **Dot-Dash**. 논거 3개를 각각 볼드 리드 문장(dot)으로 쓰고, 그 아래 2~3개 근거 대시(dash). 각 dot은 이후 본문 장의 액션 타이틀과 일치.
- 우측 또는 하단에 결정 사항·다음 단계 박스.

### 2.E 마지막 장
- "감사합니다" 금지. 마지막 장은 **결정 요청(Ask) 또는 Next Steps**: 누가·무엇을·언제까지.

## 3. 레이아웃 패턴 카탈로그

기본 그리드: 좌우 마진 0.5in, 본문 2~3컬럼, 컬럼 간격 0.25in. 카드 채움색 최소, **헤어라인(0.75pt 회색 선)으로 구획**. 둥근 모서리·그림자·그라데이션 금지.

| 패턴 | 언제 | 구성 |
|---|---|---|
| **Dot-Dash 서머리** | 첫 장 | 좌 70% 논거 3블록, 우 30% 키넘버 3개 또는 결정 박스 |
| **2컬럼 논거** | 원인→결과, As-Is→To-Be | 좌 진단, 우 함의. 가운데 화살표 하나 |
| **3컬럼 프레임워크** | 논거 3개를 한 장에 | 각 컬럼 = 소제목(주장) + 차트 1개 + 캡션 |
| **옵션 평가 매트릭스** | 전략 선택지 비교 | 행=옵션, 열=평가 기준, 셀=하비볼(○◔◑◕●), 우측 판정 열. 채택 행만 액센트 |
| **2×2** | 두 축으로 포지셔닝 | 축 이름은 양극단 라벨, 사분면마다 이름, 자사 위치 강조 |
| **워터폴** | 총량의 분해 | 시작·증감·끝. 감소는 회색, 핵심 증감만 액센트 |
| **타임라인·로드맵** | 순서·시점 | 수평 축, 마일스톤은 점, 완료·예정은 채움·외곽선으로 구분 |
| **이슈 트리** | 문제 분해 | 좌→우 가지. MECE 검사 필수 |
| **비교 타임라인(벤더별 도트)** | 경쟁사 출시 순서 | 행=벤더, 열=시간, 도트 위 용량·스펙 라벨 |

밀도 원칙: 컨설팅 덱은 **밀도가 높아도 구조가 보이면 된다**. 본문 11~12pt, 캡션 9~10pt, 각주 8~9pt. 여백을 늘려 내용을 빼지 말고, 구조를 세워 내용을 담는다.

## 4. 데이터·차트 규율

1. **차트 위에 메시지를 쓴다**: 차트 제목은 "매출 추이"가 아니라 "삼성 -54%, 노출 순위 = 낙폭 순위". 화살표·주석으로 읽어야 할 지점을 찍는다.
2. **단일 강조색**: 자사 또는 채택안만 액센트, 나머지는 회색 계열. 무지개 차트 금지.
3. **축·단위·기준**: 단위($B, %, EB, DWPD), 기준 기간(2Q22→1Q23), 계산 방식(분기 합성)을 각주에. 축 절단 시 명시.
4. **출처 없는 숫자 금지**: 모든 수치는 출처 + 수집일. 추정·전망은 "(전망)" "(추정)" 표기. 확인 안 된 주장은 "[미확인]"으로 남기지 말고 삭제하거나 확인한다.
5. **비교는 같은 축에서**: 다른 시점·다른 정의의 수치를 한 차트에 섞지 않는다. 섞어야 하면 각주로 경계 표시.
6. **하비볼 정의**: ● 충족 / ◕ 대체로 충족 / ◑ 부분 / ◔ 미흡 / ○ 미충족. 범례를 장에 넣는다.
7. **빅넘버는 문맥과 함께**: "35%" 단독 금지. "35% · 2030 AI DC NAND 워크로드 중 KV cache" 처럼 대상·시점을 붙인다.

## 6. 언어 규율

- 타이틀·스티커 = **완전 문장**(주어·서술어, 숫자 포함). 본문 = 개조식(명사형 종결, 조사 최소).
- 한 문장 한 주장. 접속사로 두 주장을 잇지 않는다.
- **em-dash(—) 금지**, 이모지 금지. 구분은 "·" ":" "," 마침표.
- 전문 용어 첫 등장 시 풀네임 병기(FDP: Flexible Data Placement). 약어 각주는 장 하단.
- 자사·경쟁사 호칭 통일(삼성 / SK그룹 / Micron / Kioxia). 존칭·감탄·수사 금지.

## 7. QA 체크리스트 (제출 전)

1. **고스트 덱 테스트**: 액션 타이틀만 복사해 순서대로 읽는다. 논증이 완결되는가. 빠진 장·순서 오류 수정.
2. **수직 논리**: 각 장 본문이 타이틀을 증명하는가. 증명 안 하는 요소 삭제.
3. **MECE**: 옵션·요인 목록에 겹침·누락이 없는가.
4. **숫자 전수 출처**: 각주 없는 수치 0건. 전망·추정 표기 확인.
5. **한 장 한 메시지**: 두 메시지 장은 분리.
6. **렌더 검사**: PDF/이미지로 렌더해 텍스트 넘침·줄바꿈 파편·겹침을 눈으로 확인. 2줄 초과 타이틀 축약.
7. **마지막 장**: Ask 또는 Next Steps인가. "감사합니다" 제거.
8. **금지어 스캔**: em-dash·이모지·"기타"·"등등"·"다양한"·"혁신적".

## 8. 이 레포(action-learning 위키)에 적용할 때

- 모든 수치·인용은 `wiki/` 페이지를 거쳐 `sources/`에 닿아야 한다. 덱에 새 숫자를 넣으려면 먼저 소스 등재 → 위키 반영 → 덱.
- 생성기는 `outputs/presentation/scripts/generate_*_consulting.cjs`(pptxgenjs, 수제 shape 차트). 산출은 `outputs/presentation/*-consulting.pptx` + `dashboard/public/downloads/` 미러. `.gitignore` 화이트리스트 등록 필수.
- 브랜드 토큰은 `samsung-memory-ppt-design-skill`의 Samsung Blue 단일 액센트를 따른다. 이 스킬은 구조·문법만 바꾼다.
- 렌더 QA: `soffice --headless --convert-to pdf` → pymupdf로 JPG → 시각 검사 후 수정.
- 덱 완성 후 `log.md`에 `build` 항목, `index.md` outputs 섹션에 등재, dashboard 변경 시 `version.js` bump.
